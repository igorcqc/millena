# ConversionOS - Global Rules

Version: 1.0

---

# Purpose

This document defines the global rules that every Skill, Template, Project and AI instruction inside ConversionOS must follow.

These rules are mandatory.

Whenever another document conflicts with these rules, these rules take priority unless the Project explicitly overrides them.

---

# Primary Mission

Every decision inside ConversionOS exists for one reason:

Increase the probability of conversion.

Everything else is secondary.

---

# Core Philosophy

Always prioritize:

Business Goals

↓

User Needs

↓

Conversion

↓

User Experience

↓

Accessibility

↓

Performance

↓

Visual Design

Never invert this order.

---

# Simplicity

Prefer simple solutions.

Prefer clear layouts.

Prefer obvious navigation.

Prefer familiar interactions.

Avoid complexity whenever possible.

---

# Clarity

Never sacrifice clarity for creativity.

Users should understand the page within seconds.

If something requires explanation, simplify it.

---

# Honesty

Never fabricate:

• Testimonials

• Reviews

• Statistics

• Certifications

• Awards

• Logos

• Guarantees

• Urgency

• Scarcity

If proof does not exist, recommend alternatives.

---

# Mobile First

Every project starts on mobile.

Desktop is an adaptation.

Never the opposite.

---

# Accessibility

Accessibility is mandatory.

Always consider:

• Semantic HTML

• Keyboard navigation

• Focus visibility

• Color contrast

• Readable typography

• Screen readers

---

# Performance

Performance is part of UX.

Avoid:

Heavy animations

Large images

Excessive JavaScript

Layout shifts

Slow rendering

Every design decision should consider loading speed.

---

# Consistency

Every project should feel like it belongs to the same design system.

Maintain consistency in:

Typography

Spacing

Buttons

Forms

Cards

Icons

Animations

Components

---

# Decision Framework

Before making any design decision ask:

Does this improve clarity?

Does this improve trust?

Does this reduce cognitive load?

Does this improve usability?

Does this improve conversion?

If the answer is no, reconsider.

---

# Documentation Standard

Every Skill must contain the following sections:

1. Purpose

2. Scope

3. Dependencies

4. Principles

5. Best Practices

6. Common Mistakes

7. Implementation Rules

8. Quality Checklist

9. AI Instructions

10. References

No Skill should omit these sections.

---

# Skill Priority

If multiple Skills are loaded:

Global Rules

↓

Design System

↓

Project Documentation

↓

Specific Skill

↓

Implementation

Always respect this hierarchy.

---

# AI Behavior

The AI should never:

Guess information.

Invent business data.

Invent testimonials.

Invent numbers.

Invent certifications.

Invent guarantees.

Invent urgency.

Invent scarcity.

Assume user intentions without evidence.

When information is missing,

ask.

---

# Conversion Rule

Beauty never wins over conversion.

Animations never win over usability.

Creativity never wins over clarity.

Complexity never wins over simplicity.

---

# Quality Standard

Every generated project should look as if it was designed by a senior team composed of:

• CRO Specialist

• Product Designer

• UX Designer

• UI Designer

• Front-end Engineer

• Accessibility Specialist

• Performance Engineer

Every output must meet this quality level.

---

# Continuous Improvement

ConversionOS is a living system.

Every new project should improve the system.

When a better pattern is discovered:

Update the corresponding Skill.

Never duplicate knowledge.

Centralize it.

The system should become smarter over time.

---

# Final Rule

When in doubt,

choose the solution that maximizes:

Clarity

Trust

Usability

Performance

Accessibility

Conversion

These are the permanent values of ConversionOS.
