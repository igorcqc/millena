# ConversionOS - Project Workflow

Version: 1.0

---

# Purpose

This document defines the mandatory workflow used to create every project inside ConversionOS.

No project should jump directly into design or development.

The process follows a strategic sequence.

---

# Overview

The ConversionOS workflow:

```
Discovery

↓

Strategy

↓

Copy Architecture

↓

UX Architecture

↓

UI Direction

↓

Technical Specification

↓

Development

↓

Quality Review

↓

Optimization
```

---

# Phase 1 — Discovery

Objective:

Understand the business and the opportunity.

Collect:

- Business information
- Product/service details
- Target audience
- Market
- Competitors
- Traffic sources
- Conversion goal

Output:

Project.md

---

# Phase 2 — Strategy

Objective:

Define the strategic direction.

Analyze:

- Positioning
- Offer strength
- Audience awareness
- Main objections
- Differentiation
- Conversion mechanism

Questions:

Why should someone choose this?

Why now?

Why trust this company?

Output:

Strategy section inside Project.md

---

# Phase 3 — Copy Architecture

Objective:

Define the persuasive communication.

Create:

- Main headline
- Supporting headline
- Value proposition
- Benefits
- Objection handling
- Proof strategy
- CTA strategy

Output:

Copy.md

---

# Phase 4 — UX Architecture

Objective:

Define the user's journey.

Determine:

- Page structure
- Section order
- Information hierarchy
- Navigation
- Interaction points

Output:

UX.md

---

# Phase 5 — UI Direction

Objective:

Define the visual experience.

Specify:

- Style direction
- Colors
- Typography
- Components
- Images
- Animations
- Design references

Output:

Design.md

---

# Phase 6 — Technical Specification

Objective:

Prepare implementation instructions.

Define:

- Framework
- Components
- Libraries
- Responsive requirements
- Performance requirements
- SEO requirements

Output:

Development.md

---

# Phase 7 — Development

Objective:

Transform documentation into a functional page.

AI developer must:

1. Read Framework documents.

2. Read applicable Skills.

3. Read project documentation.

4. Build according to specifications.

5. Maintain consistency.

---

# Phase 8 — Quality Review

Before delivery verify:

## Strategy

Does the page communicate the offer clearly?

## Copy

Is the message persuasive?

## UX

Is navigation intuitive?

## UI

Is the design consistent?

## Performance

Is the page fast?

## Accessibility

Can everyone use it?

## Conversion

Is the desired action obvious?

---

# Phase 9 — Optimization

After launch:

Analyze:

- Conversion rate
- User behavior
- Drop-off points
- Engagement

Improve:

- Copy
- Sections
- CTAs
- Forms
- Layout

Every optimization should be documented.

---

# Golden Rule

Never start with code.

Start with understanding.

The quality of the final page depends on the quality of the strategy before development begins.
